# MovieDemo – Tab Bar and "My Movies" Placeholder

Date: 2026-10-28
Status: approved by owner (2026-10-28) after builder review; decisions recorded below
Extends: `2026-10-23-moviedemo-architecture-design.md` (the architecture
spec). Everything in that document still holds unless this one says

## Intent

The app grows from one flow to two. A tab bar separates what the user can
find (the existing popular list, search and detail) from what the user has
done with movies (watchlist, seen, favourites). This step builds the tab bar
and a placeholder second tab. It does not build any of the local storage or
the real "My Movies" screens; the owner wants to pick the persistence tool
separately once the surface exists.

The point of doing the shell first is architectural: a second feature module
goes through exactly the same shape as `MovieList` and `MovieDetail`, and the
composition root learns to host more than one flow. Both are worth getting
right before any data arrives.

## Goals

- Two tabs: **Discover** (the existing flow, unchanged in behaviour) and
  **My Movies** (new).
- A new `MyMovies` feature package with the full module shape used by the
  other features: `Module`, `Provider`, `Factory`, `Router`, `Repository`,
  `ViewModel`, `ViewController`, SwiftUI `View`, previews, tests.
- The My Movies screen shows three buttons, Watchlist, Seen and Favourites,
  that do nothing yet beyond tracking an analytics event and calling their
  router method.
- `AppRouter` builds the tab bar from the two providers. The modules do not
  know they live in a tab.
- Same quality bar as the rest: Swift 6 strict concurrency, zero warnings,
  tests for the module contract, the view model and the composition root.

## Non-goals

- Any persistence. The repository exists and is wired, but every method is a
  no-op. Choosing SwiftData, Core Data, GRDB, files or anything else is a
  later conversation.
- The Watchlist, Seen and Favourites screens themselves.
- Reviews. The owner mentioned "movies they have reviewed" as a fourth
  category; it is deliberately not one of the three buttons in this step.
- Any button on the detail screen to add a movie to a list.
- Remembering the selected tab across launches. The app always opens on
  Discover.
- Changes to `MovieList` or `MovieDetail` behaviour. The only edit to
  either module is the list screen's title, which becomes "Discover".

## Anti-goals

- A `Tabs` module whose only job is to call two other modules. The tab bar is
  composition and belongs in `AppRouter`.
- The `MyMovies` module importing `MovieList`, `MovieDetail` or `APIClient`.
  It has no reason to know about them today.
- A repository protocol shaped around a storage tool that has not been
  chosen. The protocol in this step is minimal and read-only.
- Business logic in the view controller or SwiftUI view, as before.

## Constraints

- Everything in the architecture spec's Constraints section: one Swift
  Package per module, local path dependencies, `Locator` for injection,
  UIKit navigation hosting SwiftUI views, Swift 6 language mode,
  `@MainActor @Observable` view models, Swift Testing.
- The Xcode project is generated by XcodeGen from `project.yml` and is not
  tracked in git. New packages and test targets are added to `project.yml`
  and the project regenerated; `.xcodeproj` is never edited by hand.
- Tests run through `xcodebuild test -scheme MovieDemo` on an iOS simulator.
  UIKit packages cannot run under `swift test` on macOS.

## Decisions the owner made

- Two tabs named **Discover** and **My Movies**.
- Discover holds the existing flow: popular list, search, detail.
- My Movies, for now, is three no-op buttons: Watchlist, Seen, Favourites.
- The new feature is a module with the same parts as the others, including a
  repository that is a no-op for now.
- The tab bar lives in `AppRouter`, not in a module of its own.

## Decisions made by the builder (Claude) – owner may override

- **Tab bar items.** Discover uses the `safari` SF Symbol, My Movies uses
  `film.stack`. `AppRouter` sets `tabBarItem` on each navigation controller,
  so neither module knows about tabs.
- **Sections are an enum, not three methods.** `MyMoviesSection` with cases
  `watchlist`, `seen`, `favourites` carries the title, the SF Symbol and the
  analytics name. The view model has one intent, `sectionTapped(_:)`, and the
  router one method, `routeTo(section:)`. This replaces the three separate
  router methods discussed in conversation; it is the same contract with
  less repetition and a view that can iterate `allCases`. Owner confirmed.
- **Repository shape.** `MyMoviesRepository` has one method,
  `movies(in section: MyMoviesSection) async throws -> [Movie]`. The no-op
  implementation returns an empty array. The view model holds the repository
  but does not call it yet, so the storage step only has to swap the
  implementation and start calling it. A protocol with zero methods was the
  alternative and reads as a mistake.
- **Button presentation (owner decided).** Three standalone buttons, not
  list rows. A `VStack` of full-width `Button`s with `.bordered` or
  `.borderedProminent` style, each labelled with the section's symbol and
  title, centred in the screen with comfortable spacing. The builder picks
  the exact style and spacing.
- **List screen title (owner decided).** `MovieListViewController` sets
  `title = "Discover"` instead of "Movies" so the screen title matches its
  tab. The existing `MovieListModuleTests` assertion on the title changes
  accordingly. This is the only edit inside `MovieList`.
- **Analytics.** `my_movies_viewed` fires once per screen instance on first
  appear, mirroring `movie_list_viewed`. Each tap fires
  `my_movies_section_tapped` with a `section` parameter (`watchlist`, `seen`
  or `favourites`).
- **Module name.** `MyMovies`. Provider key id `"MyMoviesProvider"`.

## Module contract: MyMovies

```swift
public enum MyMoviesModule {
    public static let requiredKinds: [AnyLocatorKind] = [.analyticsClient]
    @MainActor public static func registerServices(in locator: any DependencyLocator)   // registers a closure
}
extension Locator.Kind { public static var myMoviesProvider: Locator.Kind<any MyMoviesProvider> { Locator.Kind("MyMoviesProvider") } }
extension AnyLocatorKind { public static let myMoviesProvider = Locator.Kind<any MyMoviesProvider>.myMoviesProvider.erased }

public protocol MyMoviesProvider {
    @MainActor func myMoviesViewController() -> UIViewController
}
// MyMoviesProviderImpl(locator:) stores the locator `unowned` (see note) and
// resolves .analyticsClient at call time, handing it to the factory.

protocol MyMoviesFactory {
    @MainActor func makeMyMoviesViewController(analytics: any AnalyticsClient) -> UIViewController
}
// MyMoviesFactoryImpl assembles: ViewController, NoOpMyMoviesRepository(),
// RouterImpl(viewController), ViewModel(router, repository, analytics), then bind().

enum MyMoviesSection: CaseIterable, Sendable {
    case watchlist, seen, favourites
    var title: String          // "Watchlist", "Seen", "Favourites"
    var systemImage: String    // "bookmark", "checkmark.circle", "heart"
    var analyticsName: String  // "watchlist", "seen", "favourites"
}

protocol MyMoviesRouter: AnyObject {
    @MainActor func routeTo(section: MyMoviesSection)
}
// MyMoviesRouterImpl(viewController:) holds the view controller weakly, as
// MovieListRouterImpl does. routeTo(section:) is intentionally empty with a
// comment saying the destination screens arrive with the storage step.

protocol MyMoviesRepository: Sendable {
    func movies(in section: MyMoviesSection) async throws -> [Movie]
}
// NoOpMyMoviesRepository returns [] for every section.
```

Note on the provider's locator reference: the existing providers hold the
locator strongly, which forms a `Locator → Provider → Locator` cycle that
the owner has already flagged. The new provider should hold it `unowned`
with a one-line comment. Changing the two existing providers to match is a
separate, trivial change and not part of this step unless the owner asks.

`MyMoviesViewModel` (`@MainActor @Observable final class`, conforms to
`Protocols.ViewModel` with `ViewControllerType = MyMoviesViewController`):

- state: `sections: [MyMoviesSection]` (always `MyMoviesSection.allCases`;
  exposed so the view does not reach for the enum directly).
- intents: `onAppear()` tracks `my_movies_viewed` once per instance;
  `sectionTapped(_ section:)` tracks `my_movies_section_tapped` with
  `["section": section.analyticsName]` then calls `router.routeTo(section:)`.
- holds `repository` but does not call it in this step.

`MyMoviesViewController`: `ViewModelBindable`; `bind(viewModel:)` embeds a
`UIHostingController(rootView: MyMoviesView(viewModel:))` as a child using the
same constraint code as `MovieListViewController`; `title = "My Movies"`,
`largeTitleDisplayMode = .always`; `viewWillAppear` → `viewModel.onAppear()`.

`MyMoviesView`: a `VStack` of standalone `Button`s, one per entry in
`viewModel.sections`, each labelled `Label(section.title, systemImage: section.systemImage)`
and calling `viewModel.sectionTapped(section)`. Full width, bordered style,
vertically centred. Not a `List`.

## App target changes

`AppRouter.start()`:

1. API key handling is unchanged. No key, no tabs: the missing-key screen
   stays the window root.
2. `setupLocator` additionally calls `MyMoviesModule.registerServices(in:)`
   and includes `MyMoviesModule.requiredKinds` in `verify(allOf:)`.
3. Build the Discover tab: resolve `.movieListProvider`, wrap its view
   controller in a `UINavigationController` with `prefersLargeTitles = true`,
   set `tabBarItem = UITabBarItem(title: "Discover", image: UIImage(systemName: "safari"), tag: 0)`.
4. Build the My Movies tab the same way from `.myMoviesProvider`, title
   "My Movies", image `film.stack`, tag 1.
5. `UITabBarController` with `viewControllers = [discover, myMovies]`,
   `selectedIndex = 0`, set as the window root.

Everything else in `AppRouter`, `SceneDelegate` and `AppDelegate` is unchanged.

## Behaviour summary

1. Launch with a key: tab bar with Discover selected. Discover shows the
   list screen, now titled "Discover", otherwise exactly as today; search
   and detail work as today, inside the tab's navigation stack.
2. Tap My Movies: a screen titled "My Movies" with three buttons, Watchlist,
   Seen, Favourites. `my_movies_viewed` is tracked once.
3. Tap any button: `my_movies_section_tapped` is tracked with the section
   name. Nothing else happens.
4. Switching tabs preserves each tab's navigation stack, which UIKit does
   for free.
5. Launch without a key: unchanged, the missing-key screen, no tab bar.

## Testing plan

`MyMoviesTests` (Swift Testing, `@MainActor` suites, mirroring `MovieListTests`):

- `MyMoviesModuleTests`: a fresh `Locator` with `SpyAnalyticsClient`
  registered; after `registerServices`, `missing(from: requiredKinds)` is
  empty, `.myMoviesProvider` is registered, and `myMoviesViewController()`
  returns a `MyMoviesViewController` whose title is "My Movies" after
  `loadViewIfNeeded()`.
- `MyMoviesSection` has three cases in the order watchlist, seen,
  favourites, with the titles "Watchlist", "Seen", "Favourites" (the view
  renders them in this order).
- `MyMoviesViewModelTests` with a `SpyMyMoviesRouter` and
  `SpyAnalyticsClient`:
  - `onAppear` twice tracks `my_movies_viewed` once.
  - `sections` equals `MyMoviesSection.allCases`.
  - `sectionTapped(.watchlist)` tracks `my_movies_section_tapped` with
    `section: "watchlist"` and the spy router records `.watchlist`. Same for
    the other two, or a parameterised test over `allCases`.
- `NoOpMyMoviesRepository` returns `[]` for every section (one small test,
  so the no-op is deliberate and documented).

`MovieDemoTests/AppRouterTests` extended:

- `setupLocatorRegistersEverything` adds `MyMoviesModule.requiredKinds` to
  the concatenated list and asserts `.myMoviesProvider` is registered and
  resolves to a view controller.
- A new test drives `AppRouter(window:).start()` with a window and asserts
  the root is a `UITabBarController` with two `UINavigationController`s whose
  tab bar item titles are "Discover" and "My Movies". This requires `start()`
  to be testable without a real API key: factor the tab-building into an
  internal `makeRootViewController(locator:)` that the test calls directly
  with `setupLocator(configuration: .movieDatabase(apiKey: "test"))`, and
  leave `start()` as the thin wrapper that reads the key and picks between
  the missing-key screen and that root.

All existing tests keep passing. The one exception is the list screen
title assertion in `MovieListModuleTests`, which changes to "Discover".
